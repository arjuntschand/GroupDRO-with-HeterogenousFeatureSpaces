# Protocol v4 ("V3 Updated Baselines" tab), declared 2026-09-22 before any run

Agreed with Xenia on 2026-09-21. Written down before the runs so that nothing below is chosen after
seeing test results. Applies to every method (our arms and the published baselines) on every
dataset and every no-overlap variant.

## What changes relative to the corrected pipeline of 2026-09-20

1. **Equal-group batches.** Every training step draws the same number of samples from every
   group (NHANES: 50 per group; Fed-Heart: 16 per group, see Amendments; EMBED: 32 per group, as before). Each group cycles through its
   own shuffled training rows without replacement and reshuffles when exhausted. One epoch =
   ceil(largest group's training size / per-group batch) steps. Classes are NOT balanced within a
   group (that would change the class prior and distort the loss metrics).
   Consequence to state in the paper: under this sampler "ERM" is group-balanced ERM.
2. **Uniform initial group weights** (1/G) for every method that has group weights: our GroupDRO
   and Regret-DRO arms, with and without anchors, shared or per-group, and REMIND. The initial
   weights are logged as epoch 0 so the weight plots start at 1/G.
3. **Fixed budget: 10 epochs, no early stopping, 10 seeds** (Fed-Heart: x 5 real folds). Constant
   learning rate (see Amendments). Every epoch stores, per group: validation loss and
   accuracy, test loss / accuracy / macro-F1 / AUROC (binary tasks), and the group weights.
4. **Tabular arms follow Algorithm 1 of the draft** (EMBED already did): the alignment term sits
   inside the weighted sum, J = sum_g lambda_g [(L_g - R_g) + a_align L_align_g] + a_sep L_sep; the
   weight signal is a running average (rho = 0.9) of the TRAINING-batch value L_g + a_align L_align_g;
   weights refresh every N steps with the signed excess (no clamp), N = min(50, steps per epoch).
   The validation split is therefore used for selection only, never to drive the weights.

## Reporting: five views of the same runs

The reported epoch is chosen per run (per seed, per fold) on the VALIDATION split, then the TEST
metrics of that epoch are reported. The same rule is applied to every method in a view.

| view | rule |
|---|---|
| `fixed10` | epoch 10, no selection |
| `overall` | lowest overall validation loss (sample-weighted mean over groups) |
| `worst` | lowest worst-group validation loss |
| `groupavg` | lowest group-averaged validation loss (each group's mean loss, groups weighted equally) |
| `excess` | lowest maximum validation excess, max_g (L_g - R_g) |

Note: "average over groups weighted by group size" is identical to `overall`, so `groupavg` is the
equal-weight version.

**Primary view, declared now:** `worst` for the headline tables (it is the quantity group-robust
methods target and it does not depend on a decision threshold). The other four are robustness
views and are shown whatever they say.

## Step sizes

Chosen per arm on validation, from a grid fixed here: tabular eta in {0.1, 0.5, 2, 10}; EMBED gamma
in {0.5, 2.0}. For each view, the step size is the one with the best mean validation value of that
view's rule over the 10 seeds (for `fixed10`: validation worst-group loss at epoch 10). All grid
values are run with all 10 seeds. REMIND is reported at its published gamma = 0.02 and, as a
separate row, with gamma chosen the same way from {0.02, 0.5, 2}.

## Unchanged
Real stratified 5-fold per site on Fed-Heart; per-fold references from `estimate_rstar_v3.py`
(training rows only); train-only imputation; diagonal anchors with the closed-form W2; anchors off =
weight exactly 0; anchor weights 0.1 (tabular) / 1.0 (EMBED); architectures and optimiser settings.
No test-set quantity is used for any decision.

## Families
Fed-Heart, NHANES, EMBED (main tables) and their no-overlap variants (NHANES partition, Fed-Heart
blocks rotation 0, EMBED one-view-per-group), each with our arms, the dedicated-model arm and
Reweigh / Flex-MoE / REMIND. Outputs under `runs/v4/`.

## Amendments (made on a one-seed smoke test, from VALIDATION-loss curves only, before any full run)

1. **Constant learning rate for every tabular method** instead of a cosine decay over the 10 epochs.
   With the decay, the anchored arms (which start slowly because the alignment term dominates the
   first steps) had not reached their validation minimum by epoch 10 on Fed-Heart, while the
   baselines, which never had a schedule, had. One rule for everyone, and the selection views make a
   decay unnecessary. EMBED keeps its existing schedule, which both sides already share.
2. **Fed-Heart: 16 samples per group per step** instead of 50. The sites have 83-205 training rows,
   so 50 per group is 5 steps per epoch and 50 steps in total; at 16 per group it is 13 steps per epoch
   and every method's mean validation loss reaches its minimum inside the 10 epochs (per-group arms
   around epoch 4, the full method around epoch 8, REMIND around epoch 3).
3. **Class weights:** 'auto' on NHANES for every method and none on Fed-Heart for every method. The
   earlier pipeline gave the baselines class weights on Fed-Heart and our arms none.
4. **Reweigh under equal-group batches:** its inverse-frequency weights are defined from the sampling
   frequencies, which are now equal, so Reweigh is its Soft-MoE backbone trained on group-balanced
   batches. Applying 1/n_g on top of balanced sampling would square the correction.
5. **Flex-MoE warm-up** scales with the budget (released: 5 of 60 epochs; here 1 of 10). REMIND's
   second stage starts after epoch 5, and its weights refresh every N steps like ours.
